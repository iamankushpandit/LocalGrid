# Decisions

The single list of standing decisions. Each entry says what was decided, why, and where the detail lives. The owner makes product decisions; an agent proposes and records, and never changes one silently.

To change a decision: raise the problem with the owner, and once they decide, edit the entry here, add a dated line under it, and note it in `CHANGELOG.md`.

| ID | Decision | Why | Detail |
|---|---|---|---|
| D1 | Pure ESP-IDF v6.1 for all firmware; no Arduino, no PlatformIO. Fallback v5.5.5 only if a blocker appears. | Full control of Wi-Fi, ESP-NOW, lwIP, and Kconfig; in-service release line | Design review answer 38 |
| D2 | Nodes run SoftAP only on one grid channel; nodes talk over ESP-NOW; no AP+STA tree. | Single-radio AP+STA forces channel coupling, scan outages, and parent cascades | Answers 3–7 |
| D3 | Each node has its own SSID (`LG-<NAME>`), same channel, same passphrase. | Admin phone must target the master; handhelds select by BSSID | Answer 8 |
| D4 | BLE stays in Phase 1: nodes are NimBLE broadcasters, handhelds are observers; BLE and Wi-Fi scans feed one candidate list. | Owner decision, 2026-09-15; costs are measured in the prototype | Answer 12 |
| D5 | 1:1 messages are end-to-end encrypted (X25519 pairwise key, HKDF-SHA256, ChaCha20-Poly1305); nodes reject unencrypted 1:1 text. Group and broadcast are encrypted in transit and readable by nodes. | Owner: others must not read 1:1 messages | Answer 26 |
| D6 | After a full power-off the admin re-enters time. A handheld more than 2 minutes off its node, or while grid time is unset, may only receive and send URGENT broadcasts. | Owner decision; no battery-backed clock on any board | Answers 30, 45 |
| D7 | One user per handheld: the device index is the user's address; no logins or shared devices. | Owner decision | Answer 18 |
| D8 | Handheld UI is portrait only. The keyboard may use the lower half of the screen and has letter, number, symbol, and common-emoji pages. | Owner decision | Answer 46 |
| D9 | UI is resolution-independent: pixel sizes and coordinates exist only in the board profile; screens read the resolution at runtime and use flex/grid layouts with relative sizes. | Owner decision; several screen sizes on the bench | Answer 37 |
| D10 | UI styling goes through a theme: colors, fonts, spacing, and radii come from one theme table, never literals in screen code. Phase 1 ships one theme; more themes come later. | Owner, 2026-09-15: start small, add themes in the future | Answer 37 |
| D11 | Admin web page is plain HTTP inside the master's WPA2 network. | Owner accepted; HTTPS costs ~40 KB per socket on a no-PSRAM master | Answer 29 |
| D12 | Handhelds connect to nodes over one persistent TCP session with static addressing (node n at 192.168.(4+n).1). | Reliable ordered delivery; avoids DHCP delay on every roam | Answers 10, 14 |
| D13 | Prototype has no store-and-forward: a 1:1 message to an offline user is rejected as offline. | Scope control; Phase 1 adds origin-node queues | Answer 25 |
| D14 | Code lives in the private GitHub repo `iamankushpandit/LocalGrid`. Secrets are generated by `tools/gen_secrets.py` into gitignored `firmware/common/lg_secrets.h`. | Owner decision | `.gitignore` |
| D15 | `CHANGELOG.md` is updated with every change. | Owner request | `CHANGELOG.md` |
| D16 | Protocol-core tests run on a bench board (`tests/target`), not on the PC. | WSL has no compiler and installing one needs the owner's sudo password | `docs/milestones/P1-messaging-core.md` |
| D17 | The configuration web page on the master comes next, before the laptop test client and handheld UI. | Owner, 2026-09-15: add the web page sooner rather than later | `docs/milestones/P2-node-firmware.md` |
| D20 | Every bench board gets a device ID `LG-<role>-<board>-<10 base32>` at first flash, stored in the `lgid` partition and answered by the serial `id` command. Role and board decode from `tools/bench_devices.json`; the tail hashes MAC, time, a label, and random bytes. | Owner: recognize devices by a decodable unique ID | `.claude/skills/flash/SKILL.md` |
| D21 | No MAC addresses in the repository, scripts, or tool output. Node index and name come from the identity partition. | Owner, 2026-09-15 | `tools/flash.py` |
| D22 | Flashing keeps settings by default; `--erase` is the explicit factory reset and keeps the device ID unless `--new-id` is given. | Owner asked whether flashing resets everything | `.claude/skills/flash/SKILL.md` |
| D23 | Handheld boards always use their own screen, including for testing: any firmware flashed to a handheld (test app included) shows its status and results on the display, not only over serial. | Owner, 2026-09-15 | `AGENTS.md` |
| D24 | Handheld product firmware keeps the self test and its results screen while flash and RAM allow. The plan is a quick check at every boot and the full test, including the simulated grid, on demand before Wi-Fi starts; measured suite times and memory decide what runs at boot. | Owner, 2026-09-15: liked the self test on the handhelds | `tests/target/main/test_screen.c` |
| D19 | The product is described as "an offline network" in the UI, repository, and docs, not a camp or campsite network. | Owner, 2026-09-15 | `AGENTS.md` |
| D18 | Brand icon: tent-shaped triangle of three linked nodes with a handheld at the center and radio waves at the peak. Full-color and single-color SVGs live in `assets/brand/`. | Owner asked for an icon for the product | `assets/brand/` |
