# Decisions

The single list of standing decisions. Each entry says what was decided, why, and where the detail lives. The owner makes product decisions; an agent proposes and records, and never changes one silently.

To change a decision: raise the problem with the owner, and once they decide, edit the entry here, add a dated line under it, and note it in `CHANGELOG.md`.

| D46 | **One network, like a home mesh router.** Every AP broadcasts the same SSID, **"LocalGrid Access Point"** (renamed 2026-09-18 from "LocalMesh Access Point" at the owner's word: "It should be LocalGrid Access point"; the old name was the one exception to D44), on the grid channel with the grid passphrase. | D47 | **Handhelds will relay (planned, not built).** A handheld will carry other people's messages over the grid link, so the grid becomes a mesh of people as well as APs. | D48 | **Information is sticky.** Anything a device learns that others could use (grid time and where it was set, settings, AP health, outages and their causes, availability history, and whatever is added later) must survive a restart of the device holding it and be shared with its neighbours, so a device that was away or restarted recovers it from the others. Design every new feature that way: persist it (flash for what must outlive power loss, RTC memory for history that must outlive a brownout, crash, or reset), carry a version or timestamp so newer wins and duplicates merge, and announce it on link up and periodically. A record that exists on only one device is a design gap. | Owner, 2026-09-16: "Because this is a mesh and we also have relays we need the information to be as sticky as possible between devices" and "this should be a rule when designing anything on this system". Devices restart often (brownouts, flashing, relays moving in and out of range), and one restart was wiping the very history that explains it. | Grid time itself still follows D6 after a power-off; what is sticky is the record of it. Applies to APs now and to handheld relays when D47 is built. |
| D49 | **Devices keep and send compact bytes; the browser does the decoding.** State on an ESP32 is stored in RAM, RTC memory, and flash as packed binary records (bit fields, small integers, codes instead of words), and goes between devices and to the admin page in that same binary form. Turning it into text, names, dates, durations, and graphs happens off the device: in the browser for the admin page, on the PC for tools. Text on a device exists only transiently, for a serial console line or a short protocol field that must be text. New APIs for the page are binary with a documented layout, decoded in JavaScript. | Owner, 2026-09-16: "use compute to compact and decompact the info. The browser which is off the device will have more power to decode, saving space and energy on these esp32 devices." The APs had a 6 KB JSON buffer held permanently and 1-byte-per-minute history on boards with about 50 KB of free heap. | Applies with D48: sticky records are packed. Existing JSON endpoints move to binary as they are touched. Serial console output stays text (D28) because a person reads it. |
| D50 | **A handheld chooses its own name, on the handheld.** Settings > Device > Name opens a field and keyboard; the console has `name [new name]`. A name is 1 to 23 bytes of UTF-8 and replaces the roster name everywhere it is shown. It travels as a `NAME` message (0x23): the handheld sends it to its AP when renamed and on every registration, the AP floods a newer one to every AP and pushes it to its handhelds, hands every name it holds to a handheld that registers, and floods them again on neighbour link up and every 5 minutes. The version is at least the handheld's boot counter shifted left 12 bits and grows with every rename, so it keeps growing across reboots without a second counter; every holder keeps the highest version, so copies met in any order agree (D48). Handhelds and APs keep the names they hold in flash as packed records (D49). | D52 | **Groups are made at run time, not built in.** FAMILY, KIDS and LEADERS are gone; a grid starts with no groups.
