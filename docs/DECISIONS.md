# Decisions

The single list of standing decisions. Each entry says what was decided, why, and where the detail lives. The owner makes product decisions; an agent proposes and records, and never changes one silently.

To change a decision: raise the problem with the owner, and once they decide, edit the entry here, add a dated line under it, and note it in `CHANGELOG.md`.

| D37 | Handhelds make sounds, and every sound is synthesised from a short script of tone segments: no audio samples in the firmware, because a second of 16-bit mono costs 32 KB while the whole vocabulary costs a few dozen bytes. The vocabulary is named (sent, received, urgent) so a screen cannot invent its own note, and it is played by its own task so no screen or service waits on a speaker. Sound is a board capability: the Hosyond drives its DAC on GPIO26 with the amplifier enabled by GPIO4 held LOW, and the FNK0104B's ES8311 wiring (0x18 on the touch bus, I2S MCLK 4, BCLK 5, WS 7, DOUT 8, DIN 6, amplifier enable GPIO1 active LOW) is recorded in its profile, taken from the owner's own hardware-verified board file rather than guessed. That board stays silent only until the codec backend is written. Revised 2026-09-16: the ES8311 backend is written, with the same vocabulary and volume steps, and MCLK comes from the PLL's fractional divider because the S3 has no audio PLL. | Owner, 2026-09-16: we need to add sound to the notification and sending too | `components/lg_bsp/src/lg_bsp_audio.c` |
| D38 | Notification sounds can be muted from Settings, and the choice is kept in NVS so it survives a reboot and a reflash. Muting silences every sound, the console's own tone included. Delivery markers follow the phone convention people already know: a turning arrow while sending, one tick when a node accepts, two ticks when the recipient's handheld confirms, and two ticks in the accent colour once it has been read. Revised 2026-09-16: an eye was used for read for one build, because delivered and read looked the same on the bench; they were not distinguishable because read reports never arrived at all — the nodes were running firmware older than the ack status that carries them. The owner's model is WhatsApp's, so the tick pair stays and only its colour changes. Markers and timestamps use the theme's smallest size. | Owner, 2026-09-16: sound should be mutable from settings; the received and read icons should be smaller; delivered and read must differ, because both showed two ticks | `components/lg_bsp/src/lg_bsp_audio.c`, `firmware/handheld/main/ui/ui_chat.c` |
| D39 | Settings is presented as tabs (Grid, Sound, Screen, Device), one short page each, rather than one scrolling page of sections. Lists keep the reader's scroll position across a rebuild, and readings that change continuously (free heap, signal strength) are quantised before they are allowed to trigger one: a screen that rebuilds on noise throws away the scroll position of whoever is reading it. | Owner, 2026-09-16: settings are all on the same page and should be tabbed like Chrome; and scrolling up auto-scrolls back | `firmware/handheld/main/ui/ui_settings.c`, `firmware/handheld/main/ui/ui_list.c` |
| D40 | Notification loudness is a four-step setting on the Sound tab and over the console: off, low, medium, high, kept in NVS. Four steps because that is what the hardware has -- the cosine generator attenuates in 0, -6, -12 and -18 dB and the DAC path has no gain register -- so a continuous slider would be a pretence. Off is the mute and silences ordinary cues and the console's own tone, but an URGENT broadcast ignores both the mute and the volume and always plays at full amplitude, because D6 lets urgent through when nothing else gets out. The arrival bell trades its quietest decay segments for loudness. | Owner, 2026-09-16: the Hosyond rings but very softly; we need to mute the device except for emergency, the bell should be louder, and Settings should offer mute or volume | `components/lg_bsp/src/lg_bsp_audio.c`, `firmware/handheld/main/ui/ui_settings.c` |
| D43 | The infrastructure devices are called **APs**, never nodes, in everything a person reads: handheld screens, serial console output and help text, the admin page, documentation, and this file from here on. The word is apt rather than arbitrary — each one really is a Wi-Fi SoftAP (each broadcasts the grid SSID, "LocalMesh Access Point" since D46) as well as a routing element, so "AP" names the thing a person actually meets. Code identifiers keep `node` for now (`lg_node.c`, `LG_MAX_NODES`, `node_ssid`, `LG_T_NODE_HELLO`, `firmware/node/`, the `node` console command): that rename touches the protocol core, both firmwares and the tests, and landing it on top of uncommitted marker work and a second session editing the same tree would make every one of those changes unreviewable. It is scheduled as its own commit, and until then the gap between what the code says and what a person sees is deliberate rather than an oversight. | Owner, 2026-09-16: "So do not call them Nodes I want them to be know as APs" | `docs/DECISIONS.md` D19 (the same rule about naming), `firmware/handheld/main/ui/`, `firmware/handheld/main/hh_console.c` |
| D42 | A message's marker is **one icon showing the furthest state it has reached**, and each state has its own shape rather than a repeated tick: a clock while this handheld still holds it, an up arrow once a node has taken it, a down arrow once the recipient's handheld confirms, and an open eye once that handheld showed it to its reader. Ticks were abandoned because two of them differing only in colour could not work: `accent` and `success` are the same value in the theme, so delivered and read were being drawn identically, and the second tick appearing on delivery read as "they have seen it". Group messages carry counts instead — how many handhelds have it, how many people have opened it — and collapse to "all read" once everyone has, so a number never implies a missing reader when there is none. Broadcasts stop at a delivered count, because no node ever reports having finished handing one out; there is no such message in the protocol, and a count of confirmations is better information than a claim would be. Read stays an assumption, not a fact: opening the conversation is taken as reading it, since the handheld has no camera. Marker colours come from four new theme roles (`mark_wait`, `mark_node`, `mark_delivered`, `mark_read`) rather than borrowed ones, because reusing `success` and `accent` would bake marker meaning into unrelated roles — read is a violet, deliberately outside the green palette, so the two states can never collapse into each other again. The clock is the emoji font's `U+1F553`, already in the committed subset, chosen over a true hourglass once the cost was clear: the generator emits one size only, so an hourglass would have meant a second font target. | Owner, 2026-09-16: the first check mark's duty is to say whether it was delivered and the second whether it was read; a notification must not count as read; the same check marks for different states is confusing, so use three small icons; for groups show how many delivered, how many read, and an all-read state; do not hardcode the colours, take them from the theme; mocks reviewed and Set A chosen with an hourglass, settled as the font's clock once the second-font cost was explained | `docs/mocks/message-markers.html`, `firmware/handheld/main/ui/ui_chat.c`, `components/lg_ui/src/lg_theme.c` |
| D41 | A broadcast is announced rather than mentioned. An ordinary broadcast flashes the screen with the words on it and chimes, then clears itself: meant to be caught from across a tent when the food is ready. An urgent broadcast takes the whole screen until somebody taps Dismiss, repeats a two-tone alert, and sounds even at volume off. A 1:1 or group message keeps the banner and the bell. The takeover is reserved for urgent because if every broadcast seized the screen people would learn to dismiss them unread. The screen saver can be turned off from Settings or the console, kept in NVS, and it steps aside for an alert since both draw on the top layer. | Owner, 2026-09-16: broadcasts should feel like the emergency alerts we get on the phone; add flashing announcements for when the food is ready; we should be able to disable the screen saver | `firmware/handheld/main/ui/ui_alert.c`, `components/lg_ui/src/lg_ui_screensaver.c` |

| D44 | The project will be named **LocalMesh**, but not yet. The code, repository, SSIDs (`LG-`), device IDs (`LG-`), symbols (`lg_`) and documents keep LocalGrid until the owner says to switch. Until then, write LocalGrid and do not introduce LocalMesh piecemeal. | Owner, 2026-09-16: "LocalMesh should be the name of this project but do not switch to change it yet". A partial rename would leave two names for one product. | A rename plan comes when the owner asks for it; SSID and device ID prefixes affect provisioned boards (D20, D22). |
| D45 | **No master AP.** Every AP serves the admin page and holds a full copy of the admin settings (grid name, time zone, password hash). A change made on any AP carries a version and spreads over the backbone; the newest version wins, including after a split grid rejoins. Grid time can be set on any AP and every AP that holds it keeps announcing it, so the grid loses time only when every AP has restarted (D6 still applies after a full power-off). MAIN keeps its name and becomes one AP among equals. | Owner, 2026-09-16: "can we not make the main's responsibility distributed to all aps". One board being down took away the admin page and time setting, which today blocked every non-urgent message. | Replicated settings travel encrypted under the backbone key like every backbone frame. Costs roughly 10 to 15 KB of heap per AP for the web server. |
| D46 | **One network, like a home mesh router.** Every AP broadcasts the same SSID, **"LocalMesh Access Point"** (the owner's name; the one exception to D44 before the rename), on the grid channel with the grid passphrase. All APs share one subnet, 192.168.4.0/24, and every AP answers as 192.168.4.1, so a phone that moves between APs keeps a working address and the admin page. Phone DHCP pools are split per AP so two APs never lease the same address; handhelds keep static .100 plus device index. Handhelds choose an AP by BSSID among beacons carrying the LocalGrid vendor IE and grid discriminator, and switch only with hysteresis (a clearly stronger AP for several scans, or the current AP losing backbone or going silent). | Owner, 2026-09-16: "like the google router at home, we have extenders but there is only one access point you connect to", and "call is LocalMesh Access Point". | ESP32 SoftAPs cannot bridge one Layer 2 network, so identical addressing stands in for it. A Wi-Fi list no longer shows which AP a device is on; the admin page and `status` do. Phones get no roaming steering and may hold a weaker AP until it drops. |
| D47 | **Handhelds will relay (planned, not built).** A handheld will carry other people's messages over the grid link, so the grid becomes a mesh of people as well as APs. It is a setting on each handheld, **on by default**, which a person can turn off. APs stay the always-powered spine; handhelds do not become Wi-Fi access points for phones. | Owner, 2026-09-16: "by default, relaying on CYD should be turned on. People can turn it off." Relaying extends coverage as people spread out and keeps messages moving with no AP in range. | Before it ships: per-device keys with revocation (a relay would otherwise hold the grid-wide backbone key), limits on flooding as relays move, and a look at battery cost. Supersedes D2 once built; revisit D13 (no store-and-forward). |
