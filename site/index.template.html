An offline network built from inexpensive ESP32 boards.

LocalGrid turns ordinary ESP32 boards into a self-forming network. Access points find each other and form a mesh by themselves, and touchscreen handhelds send text, emergencies, and push-to-talk voice across it. No Internet, no phones, and no cell service, ever.

How it works

There are two kinds of device. Access points are small boards with no screen that you place around the area and power; they carry the messages. Handhelds are the touchscreen devices people carry.

  1. Place and power the access points. Up to eight, in any order. They share one network name, find each other by radio, and link up on their own. Nothing to set up after the first time.
  2. Handhelds connect to a nearby access point. Each picks one with a good signal, the load spreads across access points, and a handheld switches as you walk. Up to 32 handhelds.
  3. Messages hop between access points. Private, group, and everyone messages hop from access point to access point until they reach the right people, and the sender sees when they arrive.
  4. Set it up from any phone or laptop. Join the network's Wi-Fi and open http://192.168.4.1/ to name the network, add people and groups, and set the time.

Designed to keep working

If an access point fails, only the area it covered loses signal; the rest of the network carries on. When a device restarts, it gets back what it knew from the devices that stayed on.

Every device has fixed limits built in, so a busy network slows down instead of crashing. Every design choice is written down, with the reasoning, in the project's documents.

What is ESP-NOW?

ESP-NOW is a radio protocol built into every ESP32 by Espressif, the chip's maker. It sends short packets straight from one board's Wi-Fi radio to another's. There is no router, no joining a network, and no Internet involved. LocalGrid's access points use it to talk to each other.

  1. Say hello. When an access point starts, it broadcasts a hello on the network's channel: five times, 200 ms apart, then every 2 seconds.
  2. Become neighbours. Every access point that hears the hello adds the sender as a neighbour. No pairing, no setup, and power-on order does not matter.
  3. Pass messages on. A message goes to each neighbour, which passes it on to theirs. Each access point ignores copies it has already seen, and a message stops after 3 hops, so nothing circulates forever.
  4. Work around a lost access point. A neighbour that misses three hellos (6 seconds) is dropped, and messages keep flowing through the access points that are left.

One radio, one channel

Each access point runs ESP-NOW and the Wi-Fi network the handhelds join at the same time, on one radio and one fixed channel. Handhelds use Wi-Fi to reach their access point; access points use ESP-NOW to reach each other.

Slow on purpose, for range

Access points talk at 1 Mbps, the slowest Wi-Fi rate, because slower signals reach farther. That is still plenty: one packet holds up to 1,470 bytes, enough for a whole message or a slice of voice.

Encrypted by LocalGrid

ESP-NOW's built-in encryption cannot protect messages sent to everyone at once, and it uses up connection slots the Wi-Fi side needs. So LocalGrid encrypts every message between access points itself, with a key only that network's devices hold.

What it does today

Everything below runs on the test boards. It is a prototype: expect rough edges, and read the status section before you rely on it.

Private messages stay private

A private message is encrypted on the sender's handheld and only decrypted on the recipient's. Access points carry it without being able to read it. Group and everyone messages are encrypted over the air too.

Emergencies get through

An urgent message appears on every screen, even a locked one, and the sender sees who has read it.

Push-to-talk

Hold a person or a group to talk, like a walkie-talkie. Voice is encrypted like text and levels itself so quiet and loud voices come through evenly. The Freenove handheld has a microphone and can talk; the Hosyond has none, so it listens.

Recovers after a restart

What one device knows that others need, such as who is on the network and which groups exist, is copied to its neighbours. A device that restarts gets it back from them, and the newest version always wins.

Its own clock, and GPS

The network keeps its own time. It survives a restart that keeps power, and handhelds bring it back to access points that lost it. A GPS module on MAIN sets the time from satellites and shows where MAIN is, with map links, on its admin page. A handheld can carry its own GPS too, and then it backs up the time as well.

Everyone on a map

A handheld with a GPS shares its position with the network, so the admin page can show where people are and a handheld can show how far it is from the main access point. Positions are held in memory only, never written to storage, and a handheld without a GPS simply does not appear.

Watch the network without joining it

Every access point broadcasts a sealed Bluetooth status. A laptop or phone nearby can show the health of each access point, who is online, batteries, and any alert, without joining the network. It only listens: no message text, no voice, and it never takes part.

A simple touchscreen interface

Handhelds have their own lightweight interface with a phone-style keypad. It adapts to the screen it runs on, so supporting a new display board is mostly a matter of describing its pins and screen.

Being built: LoRa

LoRa is a low-power, long-range radio that works below the Wi-Fi band. It reaches kilometres instead of a couple of hundred metres, but carries far less data. ESP32 chips have no LoRa radio, so it would mean adding a small LoRa module to a board. The modules are now fitted to the access points and the firmware for them is being written, so none of this runs yet.

Access points first

Access points too far apart for ESP-NOW will still reach each other, so two groups of access points, say at two sites a few kilometres apart, become one network. The LoRa link carries messages, alerts, who is around, positions and the time, but never live talk. A module is optional: an access point without one behaves exactly as it does today.

Handhelds later

A handheld with a module would not go silent when it walks out of Wi-Fi range: it could still send and receive messages and emergencies from much farther away, with talk returning once it is back in range. This comes after the access points, and stays optional, since each handheld needs the extra module.

What stays the same

Wi-Fi and ESP-NOW stay the main links, because they are fast enough for live talk. LoRa is the long-distance path for short, important messages. The aim is for encryption, groups, and emergencies to work the same way over either.

Tested by breaking it

The network's core claim is that it heals itself, so it is tested by attacking it: a framework randomly kills access points and handhelds, cuts their power and switches their radios off, for hours at a time, unattended, while the handhelds keep messaging each other. In a ten-hour run: 55 faults injected, 55 recovered, the backbone whole again in a median of 3.7 s. It found three bugs that code review and unit tests could not. How it was chaos tested →

Still to do

Two handhelds now carry a LoRa module alongside a GPS, but the handheld LoRa firmware is still to be written. Purpose-built handhelds are still being designed, and the access points have no cases yet. Every test so far has run on one workbench, with every board in radio range and on a cable: chaos testing in the field, on batteries and with no wires, is planned, and the ranges quoted above are estimates rather than measurements. If you have LoRa experience or boards, we would like to hear from you.

Build it with us

LocalGrid is written in the open, decisions and all. These are the places a contributor helps most.

Port a board

Describe a board's pins, screen, and touch controller in one file. If you have an ESP32 display board that is not listed, you can probably bring it up.

Test on real radios

Measure range, handover as you walk, and recovery on your hardware and in your space. A test tool switches access points off at random for hours and reports how the network recovers.

Improve the admin page

The web page every access point serves for setup. Try it here against a simulated network, no hardware needed.

Review the messaging and encryption

The code that carries and encrypts messages is plain C, checked against published test values. Careful reviewers are welcome.
